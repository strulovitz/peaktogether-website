## §3 — THE COLOR SYSTEM (this is the heart of the game)

This is NOT just "format details." This is the core UX that makes the Quake dungeon work. Read this BEFORE you design anything.

### Layer 1: Stabilo — the proof-step indicator

The figure is always shown in FULL. The "off" state = everything grey. Each "on_k" state = the WHOLE figure, but elements belonging to steps 1..k are in their group colors, elements from steps k+1..n_steps remain grey. This is cumulative reveal — you never see only "the current step's subset." You see everything you've earned so far.

```
OFF:   everything grey (unread room)
ON_1:  step 1 elements in color, rest grey
ON_2:  steps 1+2 elements in color, rest grey  
ON_3:  all elements in color (fully read)
```

The `highlight` parameter in the Asymptote file drives this. See §6.

### Layer 2: Color-matched figure↔text (the permanent identity system)

Every geometric concept has a **group name** (one of the 5 palette keys: `path`, `radius`, `construction`, `tangent`, `swept_area`). That group has an **ink color** — e.g., `path` = `#E8A200` (warm orange), `radius` = `#1E6FE0` (blue), `construction` = `#D81B60` (pink-red).

In the FIGURE: each geometric element is tagged with its group. A curve tagged `path` is drawn in orange.

In the TEXT (LaTeX proof panels): references to that element use `\cg{path}{the curve AB}` which renders "the curve AB" in the SAME orange. 

**This is the core UX.** The player reads: "Draw \cg{path}{the curve AB} and \cg{radius}{the focal radius SP}. Their intersection at \cg{construction}{point Q} forms \cg{swept_area}{triangle SPQ}." Each colored span in the text is the SAME color as the corresponding element in the figure. The player's eye connects them instantly.

### Layer 3: Multiple colors per panel (independent, per-panel choice)

A single text panel can use ANY subset of the 5 groups. Example from the Second Canon:

```
latex: "Through $C$ draw \cg{construction}{$Cc$} parallel to \cg{radius}{$SB$}, 
        meeting \cg{path}{$AB$} produced in \cg{construction}{$c$}. 
        Then triangle $SBc$ equals triangle $SAB$..."
groups_used: ["construction", "radius", "path"]
```

Three groups in one paragraph. Each `\cg{}{}` span independently colors its text to match its figure element.

The `groups_used` list is MANDATORY — it's the validation hook. Every group that appears in ANY `\cg` span in that TextBlock MUST be listed. And every listed group MUST exist in `palette.json`.

### Layer 4: OFF vs ON bake (how \cg becomes grey or colored)

The baker compiles the SAME LaTeX source TWICE:

1. **OFF bake** — redefines `\cg{g}{x}` to render x in grey_text. All text grey.
2. **ON bake** — uses the normal `\cg{g}{x}` → x in group g's ink color. Text is colored.

The `\cg` macro itself lives in `palette.tex` (generated by `palette_gen.py` from `palette.json`). The baker prepends one of two preamble versions.

### The difference between Stabilo and color-matching

| Mechanism | What it does | When it changes |
|-----------|-------------|-----------------|
| **Stabilo** (highlight) | Which figure elements are grey vs colored | Changes per proof STEP (cumulative) |
| **Color-matching** (\cg) | Which text words match which figure elements | FIXED per panel — same in ON_1, ON_2, ON_3 |

Example: In Step 1, the `path` and `construction` elements are colored in the figure; all `\cg{path}{...}` and `\cg{construction}{...}` spans are colored in the text. In Step 2, the `swept_area` elements become colored too (cumulative) — and their matching `\cg{swept_area}{...}` spans in the text were ALREADY colored (they were always colored, because color-matching is permanent, not step-dependent).

**The Stabilo controls the FIGURE. The \cg controls the TEXT. Both use the same 5 group colors. The Stabilo is cumulative per-step. The \cg is permanent per-panel.**

## §4 — THE FROZEN FORMATS (what you produce)

All live in `map/raw_models.py` in the codebase. These are your TARGET formats. You don't write code that imports them — you write JSON files that validate against them.

### Recipe format

```python
class StepGloss(BaseModel):
    model_config = ConfigDict(extra="forbid")
    index: int = Field(ge=1)
    gloss: str

class Recipe(BaseModel):
    model_config = ConfigDict(extra="forbid")
    schema_version: Literal["1.0"]
    figure_id: FigureId               # "lemma_2.f1"
    node_id: NodeId                   # "lemma_2"
    edition: str
    caption: str
    n_steps: int = Field(ge=1)
    steps: list[StepGloss]
    ops: list[RecipeOp]
```

`FigureId` = `r"^[a-z][a-z0-9_]*\.f[0-9]+$"`, `NodeId` = `r"^[a-z][a-z0-9_]*$"`

### RecipeOp vocabulary — every op has `name: OpName` (unique) + optional `draw: Draw | None`

**Points:** `FreePoint` (free_point, rough_xy), `PointOn` (point_on, path+t/near), `Intersect` (intersect, a+b+near), `Midpoint` (midpoint, a+b), `Foot` (foot, point+line), `ReflectPoint` (reflect_point, point+over)

**Lines:** `LineOp` (line, a+b), `Segment` (segment, a+b), `RayOp` (ray, a+b), `Parallel` (parallel, through+to), `Perpendicular` (perpendicular, through+to), `TangentAt` (tangent_at, curve+at), `TangentFrom` (tangent_from, curve+frm+near), `Bisector` (bisector, a+vertex+b)

**Circles:** `CircleCP` (circle_cp, center+through), `CircleCR` (circle_cr, center+radius_points|radius_value), `Circle3` (circle_3, a+b+c), `Arc` (arc, center+frm+to+direction "ccw"|"cw")

**Conics:** `EllipseFoci`, `EllipseAxes`, `ParabolaFD`, `HyperbolaFoci`, `Conic5`

**Compounds:** `Polygon` (polygon, points[] min 3), `Polyline` (polyline, points[] min 2), `Series` (series, along+to_curve+count 1..64+kind "inscribed_rects"|"circumscribed_rects"|"ordinates"|"chords"|"tangent_polygon")

**Marks:** `AngleMark` (angle_mark, a+vertex+b+right), `FloatLabel` (label, at — draw MUST be set)

### Draw — visual style per op

```python
class Draw(BaseModel):
    model_config = ConfigDict(extra="forbid")
    group: GroupName          # "path"|"radius"|"construction"|"tangent"|"swept_area"
    step: int = Field(ge=1)   # which step lights this element (step 0 = always visible? no — min 1)
    label: Optional[Label] = None
    marker: Literal["none","dot"] = "none"

class Label(BaseModel):
    model_config = ConfigDict(extra="forbid")
    tex: str                  # "$A$"
    placement: Literal["N","S","E","W","NE","NW","SE","SW","center"] = "NE"
    offset: Optional[Vec2] = None   # (float, float)
```

### TextBlock format

```python
class TextBlock(BaseModel):
    model_config = ConfigDict(extra="forbid")
    block_id: TextBlockId       # "lemma_2.s1.txt", "lemma_2.s2.txt", "lemma_2.s3.txt"
    latex: str                  # full LaTeX for this step's wall panel
    groups_used: list[GroupName]  # which groups appear in \cg{...} spans in this text
```

Use `\cg{groupname}{text}` to color spans — e.g. `\cg{path}{the curve AB}` renders "the curve AB" in the path group's ink color `#E8A200`. The palette is:

### RoomSource format

```python
class DrawingBlock(BaseModel):
    model_config = ConfigDict(extra="forbid")
    block_id: DrawBlockId       # "lemma_2.s1.fig", "lemma_2.s2.fig", "lemma_2.s3.fig"
    figure_id: FigureId         # "lemma_2.f1"  -- SAME for all steps
    highlight_step: int = Field(ge=1)  # matches step_index

class StepPair(BaseModel):
    model_config = ConfigDict(extra="forbid")
    pair_id: PairId             # "lemma_2.s1", "lemma_2.s2", "lemma_2.s3"
    step_index: int = Field(ge=1)
    drawing: DrawingBlock       # present for all 3 steps
    text: TextBlock

class CeilingEq(BaseModel):
    model_config = ConfigDict(extra="forbid")
    eq_id: EqId                 # "lemma_2.eq0"
    latex: str

class FigureDecl(BaseModel):
    model_config = ConfigDict(extra="forbid")
    figure_id: FigureId
    asy_path: str               # e.g. "figures/lemma_2.f1.asy"
    recipe_path: str            # e.g. "recipes/lemma_2.f1.json"
    n_steps: int = Field(ge=1)

class RoomSource(BaseModel):
```

- `TextBlockId` = `r"^[a-z][a-z0-9_]*\.s[0-9]+\.txt$"` — e.g. `"lemma_2.s1.txt"`
- `EqId` = `r"^[a-z][a-z0-9_]*\.eq[0-9]+$"` — e.g. `"lemma_2.eq0"`

## §6 — THE ASYMPTOTE FILE (what figure.lemma_2.f1.asy must look like)

The `.asy` file imports `prooffig` (the project's standard preamble that handles the `highlight` parameter, palette color definitions, and rendering setup). The file must support:

- `highlight=0` → everything grey (off state)
- `highlight=1` → Step 1 elements in color, rest grey
- `highlight=2` → Steps 1+2 elements in color, rest grey
- `highlight=3` → All elements in color

The `prooffig` preamble (not your job — it already exists in the bake tools) provides:
- The `highlight` parameter (integer, 0 to n_steps)
- Color definitions for each group (grey, path, radius, construction, tangent, swept_area)
- Helper functions for conditional drawing

Your `.asy` file just USES these. Pattern:

```asymptote
// figure.lemma_2.f1.asy
import prooffig;  // provides highlight, colors, conditional-draw helpers

// Geometric elements
// ... define points, curves, rectangles ...

// Each element wrapped with highlight check
if(highlight >= 1) { draw(curve, path_color); } else { draw(curve, grey); }
if(highlight >= 1) { draw(baseline, construction_color); } else { draw(baseline, grey); }
if(highlight >= 2) { draw(inscribed_rects, swept_area_color); } else { draw(inscribed_rects, grey); }
if(highlight >= 3) { draw(circumscribed_rects, radius_color); } else { draw(circumscribed_rects, grey); }
```

**CRITICAL: Do NOT invent the prooffig API from memory.** The prooffig preamble already exists in the codebase. DeepSeek can give you its exact interface (function names, color variable names, the `highlight` parameter convention). If you need to know it, ask: "What is the exact prooffig API — function names, color variables, the highlight parameter mechanism?"
